# Novelty / related-work review (limited: 8 standard web searches on 2026-11-13, not a systematic survey)

| # | Work | What it does | Link to EvidenceRun | What it does NOT do |
|---|---|---|---|---|
| 1 | Aliannejadi et al., *Asking Clarifying Questions in Open-Domain Information-Seeking Conversations* (Qulac), 2019 — https://arxiv.org/abs/1907.06554 | Resolves ambiguous/incomplete queries by asking clarifying questions; oracle clarification gives large retrieval gains | Motivates "query gets more informative over time"; clarification is the *mechanism* that produces our "later" state | Does not train a retriever on realistically incomplete states; no technical-support troubleshooting; facets are synthetic/crowd |
| 2 | *Exploration Study of Mixed-initiative Query Reformulation in Conversational Passage Retrieval* — https://arxiv.org/abs/2307.08803 | Detects "incomplete" queries (rule-based) with a dense retriever (TCT-ColBERT) in TREC CAsT | Closest to partial queries + dense retrieval | Rule-based detection, no retriever training on incomplete states, no historical solution targets |
| 3 | Yu et al., *Technical Question Answering across Tasks and Domains* (NAACL 2021) — https://arxiv.org/abs/2010.09780 | TechQA: retrieval + reading for IBM tech-support questions, low lexical overlap | Same domain (support Q → solution document) | Uses the final question only; no temporal states |
| 4 | Thakur et al., *BEIR* (incl. CQADupStack, Stack Exchange duplicate retrieval) — https://arxiv.org/abs/2104.08663 | Zero-shot IR benchmark with Stack Exchange forums | Shows generic Stack Exchange retrieval is an existing, well-studied task | Query = a full final question → our task differs only if the *prefix-state* design adds something |
| 5 | Zhuang & Zuccon / *Typo-Robust Representation Learning for Dense Retrieval* — https://arxiv.org/abs/2306.10348 ; RoDR (IJCAI 2022) — https://www.ijcai.org/proceedings/2022/275 | Train dense retrievers on perturbed/augmented queries for robustness | Direct analogue of "FT-Random" (random perturbation) as the control | Perturbations are typos / paraphrase, not information-structured incompleteness |
| 6 | Baltes et al., *SOTorrent* — https://arxiv.org/abs/1803.07311 | Reconstructs Stack Overflow post revision history | Validates PostHistory-based reconstruction of earlier post versions | Not a retrieval study |
| 7 | WixQA — https://arxiv.org/abs/2505.08643 | Enterprise support RAG benchmark with multi-step answers | Related troubleshooting-retrieval benchmark | No partial-state queries |

**Gap that can be claimed (hedged):** among what we found, none trains a retriever on *source-grounded, time-ordered partial problem descriptions* (revisions/asker replies before the first answer) and compares information-structured incompleteness (FT-Aware) with random incompleteness (FT-Random) and complete text (FT-Full). This is an absence-of-evidence finding from a short search; a proper literature review is still required before the midterm (course asks ≥3 papers in a comparison table — met in count, not yet in table form).

**What is NOT novel:** generic retrieval of Stack Exchange answers (BEIR/CQADupStack), query augmentation for robustness, clarifying-question retrieval. Novelty rests on (a) the temporally reconstructed prefix benchmark and (b) the controlled Aware-vs-Random comparison — and only if the pilot shows the later state really adds retrievable information. **The measured early→later gain (below) is small, which weakens (b).**
